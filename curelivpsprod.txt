# NOTES
# ============================================================

# .env files are NOT in git — they live only on the VPS.
# Never overwrite them during deploy.
# Location: ~/cureli-erp-devs/backend/.env
#
# If you add new env vars locally, you must manually add
# them to the VPS .env before restarting pm2.
#
# Prisma:
#   "npx prisma migrate deploy" runs pending migrations only.
#   It does NOT reset data. Safe to run on every deploy.
#   If you have NO new migrations, it exits cleanly — still safe.
#
# pm2 restart vs reload:
#   "pm2 restart" = kills + restarts (tiny downtime, ~1s)
#   "pm2 reload"  = zero-downtime reload (use if you care)
#   For current traffic levels restart is fine.
#
# nginx reload vs restart:
#   "sudo systemctl reload nginx" = graceful, no downtime.
#   Only needed if nginx config changed.
#   If only frontend files changed, reload is optional
#   but harmless to always run.



# ============================================================
# RECOVERY — Accidentally coded on prod instead of dev
# ============================================================
#
# Scenario:
# You've been working for hours (or days) on the "prod" branch.
# You have tons of uncommitted changes across backend,
# pharmacy-web, cadmin-web, landing-web — maybe new files,
# maybe deleted files, maybe edits everywhere.
# You have NOT committed or pushed any of it.
# Goal: move ALL of it safely to "dev" without losing a single line.
#
# ----------------------------------------------------------
# STEP 1 — Confirm you're on prod and see the damage
# ----------------------------------------------------------

git branch --show-current
# should say: prod

git status
# you'll see a wall of red/green — that's fine, don't panic

# ----------------------------------------------------------
# STEP 2 — Stash EVERYTHING (including new/untracked files)
# ----------------------------------------------------------
# The -u flag is critical. Without it, brand new files you
# created (new components, new routes, new .prisma files, etc.)
# will NOT be stashed and will be left behind on prod.

git stash push -u -m "WIP: moving work from prod to dev"

# Verify prod is now clean:
git status
# should say: "nothing to commit, working tree clean"

# Verify your stash was saved:
git stash list
# should show something like:
#   stash@{0}: WIP: moving work from prod to dev

# ----------------------------------------------------------
# STEP 3 — Switch to dev
# ----------------------------------------------------------

git switch dev

# If dev is behind origin, pull first:
git pull origin dev

# ----------------------------------------------------------
# STEP 4 — Restore your changes onto dev
# ----------------------------------------------------------

git stash pop

# This applies ALL your changes (edits + new files + deletes)
# onto the dev branch, exactly as they were.

# ----------------------------------------------------------
# STEP 5 — Verify
# ----------------------------------------------------------

git status
# you should see the same wall of changes you had before,
# but now on the dev branch

# Quick sanity check — make sure your key files are there:
# (adjust paths to whatever you were working on)
#   git diff --stat

# ----------------------------------------------------------
# STEP 6 — Commit and push on dev
# ----------------------------------------------------------

git add .
git commit -m "feat: your actual commit message here"
git push origin dev

# ----------------------------------------------------------
# STEP 7 — Clean up prod (if needed)
# ----------------------------------------------------------
# If you accidentally committed something to prod earlier
# (before you realized the mistake), you need to undo it:

git switch prod
git log --oneline -5
# find the commit hash of your accidental commit, then:
git revert <accidental-commit-hash>
git push origin prod

# ----------------------------------------------------------
# TROUBLESHOOTING
# ----------------------------------------------------------
#
# "git stash pop" says CONFLICT:
#   This means dev already has changes to the same files.
#   Open the conflicted files, look for <<<<<<< markers,
#   resolve them, then:
#     git add .
#     git stash drop    (removes the stash since it's applied)
#     git commit -m "feat: resolved stash conflicts"
#
# "git stash pop" says "already up to date" or nothing happens:
#   Your stash might be empty. Check:
#     git stash show stash@{0} --stat
#   If it shows files, try:
#     git stash apply stash@{0}
#   (apply doesn't delete the stash, so you can retry safely)
#
# You stashed WITHOUT -u and lost new files:
#   New/untracked files are NOT in the stash. They're still
#   sitting on the prod branch as untracked files.
#   Switch back to prod, grab them, switch to dev:
#     git switch prod
#     git status          (your new files are still here)
#     git stash push -u -m "grabbing missed files"
#     git switch dev
#     git stash pop
#
# You want to see what's in a stash before popping:
#     git stash show stash@{0} --stat     (file list)
#     git stash show stash@{0} -p         (full diff)
#
# You have multiple stashes and don't know which is which:
#     git stash list
#     git stash show stash@{0} --stat
#     git stash show stash@{1} --stat
#   Pop the right one:
#     git stash pop stash@{1}
